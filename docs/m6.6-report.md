# M6.6 report: config layer

**Done by the plan's criteria**, with the limits listed at the end. The decisions are in [ADR 0011](adr/0011-config-layer.md), which is now accepted.

## Verification

- Format, lint, and typecheck (`pnpm -r typecheck`, as CI runs it) are clean. The repository has 1,251 unit tests (1,101 at the end of M6.5), all passing, and the phantom's 24 Python tests.
- `pnpm matrix` (all variants, `inline` and `url`): 60 of 60 rows pass, with the new `config` scenario in each framework.

## What running it found

| Problem | Cause | Fix |
|---|---|---|
| After the `i` key (or the invert button, or `viewport.toggleInvert()`), the state, the overlay ("Inverted"), and the pressed state of the toolbar button stayed as they were | Cornerstone reports a change of window or camera, not a change of invert alone, so the viewer was never told. Found because the config scenario checked the state after a key the file bound to invert | The engine tells the viewer's listeners after it sets invert, and the scenario checks the state and the overlay |
| A union in the schema reported "no option matched" with no path | Zod keeps the problems of each option inside the union issue | `parseViewerConfig` shows the problems of the option that got furthest |
| `superRefine` checks (a key bound twice, two buttons with one id) do not run while the shape has other problems | Zod skips them when the shape fails | Left as it is: they show once the shape is right. Both are tested |

## Changes to the API

- **Core:** `createViewer({ config, commands })`, `viewer.config` (`get`, `apply`), `viewer.commands`, the event `config:changed`, `parseViewerConfig`, `viewerConfigJsonSchema`, the types and name lists of the config, `renderOverlay`, and `OverlayOptions.corners`. `OverlayInfo.metadata` and `PanelDefinition.icon` were added earlier in the milestone or in M6.5.
- **Elements:** `config`, `commands`, `config-url`, and `config-origins` on `<dv-viewer>`, and `config:changed` in the toolbar's events. **React and Vue:** `config`, `commands`, `configUrl`, `configOrigins`.
- **Changed on purpose:** `theme`, `palette`, and `toolbarLabels` of `<dv-viewer>` (and the props) are unset until a page sets them, so a config can decide. Before they started as `dark`, `default`, and `tooltip`. A page that set one is unchanged, and an unset one looks the same as before when there is no config.
- **Changed:** the port's `RenderingPort` is untouched. `ViewerCoreOptions.overlay` takes `corners`. The removal of an overlay line is `{ id, kind: 'remove' }`.

## Not done, or not proven

- **No editor tooling beyond the schema.** `$schema` gives completion and checks in an editor that understands JSON Schema. A command of the host and a tag keyword are not in it.
- **`windowLevelPresets` replace; they do not merge by id.** To add to the built-in list a config must list all of them, as the code option does. There is still no call to add one preset while the viewer runs, only a layer with the whole list.
- **`tools.active` is read at the start.** A layer given to `apply` may not have it.
- **A tag line shows the first value or all of them as text.** There is no format for a multi-valued number, a unit, or a code string lookup (for example, `PatientSex` as a word).
- **A host's own toolbar or panel icons are not possible**, only the shell's 28. A config can name a picture the shell does not have, and gets a text button.
- **`config-url` is fetched once, when the viewer starts.** Changing the file later changes nothing until the element starts again.
- **Chromium only**, as before.
